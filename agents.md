## Porting Rules

### {{MODE_UPPER}} Mode Rules

**Phase 0 — Establish baseline**
- Read `kands://status` to confirm current date and available toolkits
- Read `kands://goal` to understand the ultimate goal + guardrails
- Run `detect_toolchain(gpu_vendor=\"auto\", host_compiler=\"auto\")` to verify what's actually installed
- Run `--perf-tracing` to capture baseline performance BEFORE any changes

{% if MODE == "strict" %}

- **Reject common myths before coding** — call `reject_common_pattern(\"hipify-perl handles everything\", arch=\"{{TARGET_ARCH}}\")` to catch anti-patterns
- **Every kernel file** MUST be audited for arch-specific branches (`#if`, `__HIP__`, `__CUDA_ARCH__`, `gfx1XX`).
- **Every `#ifdef`** must be resolved — no \"assume it compiles, try later.\"
- **Feature gates** must be traced through the full call graph.
- **Parity tests must pass** before any performance work begins.
- **Perf-tracing baseline must be captured** before changes, and re-run after.
- **No placeholder/stub code** — every kernel must produce real output. If a feature is missing, implement a correct (if slower) fallback path.
- **Never skip numerical verification** — call `verify_numerical_equivalence(arch, workload, source_values, target_values)` after each port.
- **No \"works on my machine\"** — document the exact toolchain version + driver.

{% else %}

- **Scrutinize** — even in loose mode, call `reject_common_pattern()` to catch obvious traps
- Focus on the **hot path kernels** (top 10 by perf-tracing) first.
- Use existing **fallback paths** where arch features differ (F32 attention vs WMMA).
- **Best-effort parity** — get the model running, optimize later.
- Document assumptions as `TODO(kands:strict-review)` for a follow-up strict pass.
- **No stubs** — even in loose mode, fallbacks must be correct (just not optimized).

## Reject & Experiment Methodology

Before implementing any \"common wisdom\" porting technique, verify it isn't an anti-pattern:

1. **Reject phase** — `read kands://radical-experiments` for the anti-pattern list
2. **Call** `reject_common_pattern(common_idea=\"hipify-perl handles everything\", arch=\"{{TARGET_ARCH}}\")`
3. **Get radical ideas** — `radical_experiment_plan(arch=\"{{TARGET_ARCH}}\", kernel_type=\"gemm\", experiment_type=\"all\")`
4. **Validate every experiment** with `verify_numerical_equivalence()` — never deploy untested
5. **Record results** — `record_performance(arch={{TARGET_ARCH}}, workload=\"gemm\", tok_per_s=X)`
6. **Save learnings** — `export_contribution(engine_name=\"{{ENGINE}}\", arch=\"{{TARGET_ARCH}}\")`

**Key insight:** RDNA has 1000+ extensions, but most go unused because developers copy CUDA patterns. Use native RDNA approaches — DPP shuffles, v_dot4 intrinsics, wave32 scheduling — instead of porting CUDA idioms.

## Key Concepts

### Copy vs Adapt vs Rewrite

| Strategy | When to use | Mode |
|---|---|---|
| **Copy** | Same backend, minor feature diff | strict: verify intrinsics |
| **Adapt** | Different backend, similar arch features | strict: bit-exact parity |
| **Rewrite** | Different paradigm or no feature parity | strict: new parity harness |

Read `kands://porting-strategies` for the full decision flow.

### Vulkan on AMD Gotcha

> **CooperativeMatrix is broken on AMD Vulkan drivers.** Use DP4a (`GL_KHR_shader_integer_dot_product`) for matmul.

Read `kands://isa-references` for the full Vulkan compatibility matrix.

## Iterative Optimization Loop (sherlock-it)

When the user says \"I need X optimized\":

1. **Declare** — identify the target from `--perf-tracing` output
2. **Trace** — `sherlock-it trace` to find sub-component bottlenecks
3. **Dissect** — use diagnostic traps (dispatch, memory, instruction, sync)
4. **Hypothesize** — form testable hypotheses, rank by info-gain/cost
5. **Experiment** — change ONE variable, measure
6. **Verify** — CPU oracle parity + recompute perf
7. **Record** — `record_performance(arch, workload, tok_per_s)`
8. **Repeat** — until target met

Read `kands://diagnostics` for full method documentation.

## Recommended Workflow

1. **Census**: `discover_kernels(repo=REPO_ROOT)` — get the full inventory
2. **Compare**: `compare_archs(arch_a=\"{{SOURCE_ARCH}}\", arch_b=\"{{TARGET_ARCH}}\")` — find feature gaps
3. **Query**: `query_kernel_features(repo, pattern=\"wmma|dot4|mma|gfx\")` — find arch branches
4. **Detect**: `detect_toolchain(gpu_vendor=\"auto\", host_compiler=\"auto\")` — find actually-installed compilers on this machine
5. **Estimate**: `estimate_performance(arch=\"{{TARGET_ARCH}}\", workload=\"flash_attn\")` — see what's achievable
6. **Target**: `compare_to_target(arch=\"{{TARGET_ARCH}}\", workload=\"flash_attn\", target_tok_per_s={{TARGET_TOK_PER_S}})` — gap analysis
7. **Auto-plan**: `autonomous_port(repo_path=REPO_ROOT, source_arch=\"{{SOURCE_ARCH}}\", target_arch=\"{{TARGET_ARCH}}\")` — full report
8. **Search online** (if needed): `search_online(query=\"ROC 10.1 install Windows\", max_results=5)` — current URLs + guides
9. **Reject myths**: `reject_common_pattern(\"hipify-perl handles everything\", arch=\"{{TARGET_ARCH}}\")` — catch anti-patterns
10. **Radical ideas**: `radical_experiment_plan(arch=\"{{TARGET_ARCH}}\", kernel_type=\"gemm\", experiment_type=\"all\")`
11. **Trace**: `generate_tracing_plan(repo=REPO_ROOT)` — STRACE instrumentation plan
12. **Profile**: `--perf-tracing` before/after, use `diff_perf_traces()`
13. **Verify**: `verify_numerical_equivalence(arch=\"{{TARGET_ARCH}}\", workload=\"flash_attn\", source_values=[...], target_values=[...])` — CPU oracle parity
14. **Export**: `export_contribution(engine_name=\"{{ENGINE}}\", arch=\"{{TARGET_ARCH}}\")` — share findings

## Hard Rules (Never Break)

- **Never add placeholder/stub code** — every kernel must produce real output
- **Never assume intrinsics are portable** — verify via `kands://isa-references`
- **Never skip parity testing** — CPU oracle (`verify_numerical_equivalence`) is the gold standard
- **Reject common porting myths** — call `reject_common_pattern()` before implementing \"standard\" techniques
- **Never deploy experimental code untested** — radical experiments MUST be verified against CPU oracle
- **Never include personal data** — emails, paths, git hashes are auto-sanitized
- **Never ignore the current date** — search tools use date for filtering
- **Never modify files out of scope** — check `kands://goal` for guardrails
- **Never hardcode toolchain paths** — use `detect_toolchain()` to find what's actually installed
